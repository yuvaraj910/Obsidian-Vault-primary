# Weekly Completions and Documentation

Use this workflow during the weekly Kaizen Day / Systems & Learning
Optimization session to consolidate the week's coding work and prepare
the next week.

-   **Week of:**
-   **Main learning focus:**
-   **Projects worked on:**

### Progress

-   [ ] List the features, exercises, or milestones completed.
-   [ ] Identify unfinished work and blockers.
-   [ ] Select the project or changes to review.

## 2. Review Code

-   [ ] Inspect the changes made during the week.
-   [ ] Check correctness, readability, naming, and structure.
-   [ ] Remove accidental debug code or unrelated changes.
-   [ ] Review the Git diff and confirm only intended files are
    included.

## 3. Test and Fix

-   [ ] Run the project or relevant tests.
-   [ ] Verify the expected behavior.
-   [ ] Fix important bugs and retest.
-   [ ] Record any known limitations that remain.

## 4. Commit and Push to GitHub

-   [ ] Check `git status`.
-   [ ] Review `git diff`.
-   [ ] Stage only intended files.
-   [ ] Create a clear, meaningful commit message.
-   [ ] Push to the correct remote and branch.
-   [ ] Verify the commit appears on GitHub.

**Repository:** **Branch:** **Commit:** **GitHub URL:**

> Never commit secrets, API keys, passwords, local environment files, or
> unrelated personal data. If tests fail, the push is blocked, or the
> work is not ready, record the actual status rather than claiming it is
> complete.

## 5. Document in Obsidian

-   [ ] Update the existing project note or create one only if needed.
-   [ ] Summarize what the project does and its current state.
-   [ ] Record key concepts learned and important implementation
    decisions.
-   [ ] Document significant bugs, their causes, and fixes.
-   [ ] Link the relevant repository and important notes.
-   [ ] Record unfinished work and the next concrete step.

instructions. Do not modify the `Databases` folder unless explicitly

## 6. Update Notion

-   [ ] Update the project's status.
-   [ ] Record completed milestones.
-   [ ] Record skills practiced or improved.
-   [ ] Add remaining tasks and blockers.
-   [ ] Link the GitHub repository and relevant Obsidian note if
    appropriate.

## 7. Prepare the Next Week

-   [ ] Choose the main learning priority.
-   [ ] Choose the next project task or milestone.
-   [ ] Identify one weakness to work on.
-   [ ] Make the first task concrete and actionable.

## Completion Criteria

The weekly workflow is complete when: 1. The week's work has been
reviewed and tested, or remaining issues are explicitly recorded. 2.
Intended code has been committed and pushed, or the reason it has not
been pushed is documented. 3. Obsidian project documentation is updated.
4. Notion progress is updated. 5. The next week's first task is clear.
